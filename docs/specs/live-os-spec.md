# live os — Spec

> ชื่อ "live os" เป็นชื่อชั่วคราว ยังไม่ตรงกับคอนเซ็ปต์ (ตั้งใจให้เป็นเหมือน "life OS" แต่ยังไม่ยืนยัน) เปลี่ยนได้ทีหลัง

## เจตนาและเหตุผล (ทำไม)

ผู้ใช้เคยทำ LifeSeed (<https://github.com/devf51/LifeSeed>) แอปจัดการชีวิตที่ต้องกรอกทุกอย่างเอง การกรอกเองทำให้ใช้ยาก
live os คือเวอร์ชันใหม่ที่ผู้ใช้ **พิมพ์เล่าเป็นภาษาคนในแชท** แล้วระบบจดให้ เตือนให้ และตอบคำถามย้อนได้ ให้ความรู้สึกเหมือนเพื่อนสนิท

ความสำเร็จตามคำของผู้ใช้: "ระบบที่ทำงานให้ฉันสบายใจเวลาใช้มัน ระบบที่เตือนฉัน สร้างวินัยให้ฉัน ไม่ว่าการงาน การเรียน หรือการเงิน"

## ผู้ใช้

ผู้ใช้คนเดียว คือเจ้าของโปรเจกต์เอง (เป้าหมายแรก) ไม่มีระบบหลายบัญชี การขยายไปให้คนอื่นใช้เป็นเรื่องอนาคต

## สิ่งที่ต้องมี (เป้าหมาย)

1. **แชทภาษาธรรมชาติเป็นช่องทางหลัก** พิมพ์ประโยคปกติ ไม่มีฟอร์ม เช่น "กินข้าว 80 บาท", "ศุกร์หน้าบ่ายสามหมอฟัน"
2. **จดให้สามด้าน** (มาจาก LifeSeed ที่ผู้ใช้ใช้จริง):
   - **การเงิน:** รายรับ รายจ่าย หมวดหมู่ งบประมาณต่อหมวด
   - **ตัวจัดงาน:** งาน ลำดับความสำคัญ วันครบกำหนด รวมถึงตารางเรียนและนัด (เก็บเป็นงาน/เหตุการณ์ที่มีเวลา)
   - **นิสัย:** สร้างและติดตามนิสัย
3. **เตือนเอง** เมื่อ
   - ใกล้ถึงเวลาเรียน
   - ใกล้ถึงนัดที่ผู้ใช้เล่าไว้
   - ใช้จ่ายเกินงบที่ผู้ใช้ตั้งไว้
   เตือนเฉพาะเรื่องที่ผู้ใช้เคยบอกไว้ ไม่ทักพร่ำเพรื่อ
4. **ถามย้อนได้** เช่น "เดือนนี้ใช้ไปเท่าไหร่" และ **คุยเรื่องทั่วไปได้** เหมือนเพื่อน
5. **จดแล้วต้องแม่น** ยอดเงิน วันที่ และเวลาต้องถูกต้อง (ผู้ใช้ไม่ได้ระบุเกณฑ์ตัดสินใจ ดูหัวข้อ "การตัดสินใจของผู้เขียน")

## สิ่งที่ไม่ใช่เป้าหมาย

- ระบบ gamification (ต้นไม้ XP) จาก LifeSeed ผู้ใช้ไม่เอา
- หลายผู้ใช้ บัญชี การล็อกอิน (ตอนนี้)
- Dashboard และกราฟเป็นแกนของเวอร์ชันแรก (จุดขายคือการคุยแทนการกรอก)
- การเตือนนิสัยแบบที่ผู้ใช้ไม่ได้ตั้งไว้ (ผู้เขียนยังไม่เพิ่มเอง)

## สิ่งที่ต้องหลีกเลี่ยง (ถือว่าล้มเหลวแม้ทำงานได้ทางเทคนิค)

- จดผิด (ยอดเงิน วันที่ เวลา) แล้วผู้ใช้ไม่รู้ตัว จะทำให้การเตือนทั้งหมดไร้ประโยชน์และเสียความไว้ใจ
- ทักเตือนพร่ำเพรื่อจนน่ารำคาญ
- ให้ความรู้สึกเป็นฟอร์มหรือเครื่องมือเทคนิคแทนที่จะเป็นเพื่อน (ผู้ใช้ต้อง "สบายใจ" เวลาใช้)

## ข้อจำกัด

- ผู้ใช้เคยใช้ Next.js + React + Zustand (เก็บข้อมูลในเครื่อง ไม่มีเซิร์ฟเวอร์) ใน LifeSeed นี่เป็นข้อมูลอ้างอิง **ไม่ใช่ข้อจำกัดที่ผู้ใช้กำหนด** ขั้น design ตัดสินเอง
- LifeSeed เก็บข้อมูลในเครื่องและไม่มีเซิร์ฟเวอร์ การที่บอททักหาผู้ใช้ตอนไม่ได้เปิดแอปเป็นสิ่งที่ระบบเดิมไม่มี ต้องถูกแก้ในขั้น design
- ภาษาหลักของผู้ใช้คือภาษาไทย บอทต้องเข้าใจและตอบภาษาไทยเป็นธรรมชาติ

## ข้อมูลที่ต้องเก็บ (ระดับความต้องการ)

รายการเงิน (จำนวน ประเภทรับ/จ่าย หมวด วันที่), งบต่อหมวด, งาน/นัด/ตารางเรียน (ชื่อ เวลา ความสำคัญ สถานะ), นิสัย (ชื่อ ความถี่ บันทึกการทำ) ข้อมูลเงินและตารางเป็นข้อมูลส่วนตัว

## สิ่งที่ปล่อยให้ขั้น design

ช่องทางที่บอททักผู้ใช้ (แอปแชทที่มีอยู่ หรือแอปของตัวเอง) สถานที่เก็บข้อมูล แพลตฟอร์ม ภาษาโปรแกรม โมเดล AI วิธีเก็บข้อมูลให้เป็นส่วนตัว วิธีเรียกให้ผู้ใช้ยืนยันเมื่อบอทไม่มั่นใจ ชื่อผลิตภัณฑ์

## การตัดสินใจของผู้เขียน (ผู้ใช้ตรวจ/แก้ได้)

- ตารางเรียนและนัดเก็บเป็นเหตุการณ์ที่มีเวลาในตัวจัดงาน ไม่แยกระบบ
- การเตือนนิสัยไม่อยู่ในเวอร์ชันแรก เว้นแต่ผู้ใช้ตั้งไว้เอง
- ความแม่นยำสำคัญกว่าความเร็ว เมื่อบอทไม่แน่ใจ (เช่น "ศุกร์หน้า" กำกวม) ควรถามยืนยันสั้นๆ แทนการเดา
- **ยืนยันโดยผู้ใช้:** ทุกครั้งที่จด บอททวนสั้นหนึ่งบรรทัด (เช่น "จดแล้ว: ข้าว 80 บาท") และแก้หรือยกเลิกได้ทันที ถามก่อนจดเฉพาะเมื่อกำกวม
- **ยืนยันโดยผู้ใช้:** การเตือนต้องมาถึงผู้ใช้แม้ไม่ได้เปิดแอป เตือนพลาดหรือช้าถือว่าร้ายแรงเกือบเท่าจดผิด ระบบจึงต้องทำงานตลอดเวลา
- **ยืนยันโดยผู้ใช้:** เวอร์ชันแรกเริ่มจากข้อมูลว่าง ไม่ย้ายข้อมูลจาก LifeSeed
- งบประมาณนับเป็นรอบเดือนปฏิทิน
- ตารางเรียนเป็นเหตุการณ์ที่ซ้ำรายสัปดาห์ได้ นิสัยตั้งความถี่ได้ (ทุกวัน / N ครั้งต่อสัปดาห์ / บางวันของสัปดาห์)
- ค่าเริ่มต้นการเตือน: เรียนและนัดเตือนก่อน 30 นาที (ปรับต่อรายการได้), งบเตือนที่ 80% และ 100% ครั้งละหนึ่งครั้งต่อรอบ, ไม่เตือนเรื่องที่ผู้ใช้ไม่ได้ตั้งไว้ ช่วงเวลาเงียบและเพดานต่อวันให้ขั้น design กำหนด
- การคุยทั่วไปคือคุยต่อเนื่องแบบเพื่อน จำข้อมูลที่จดไว้ได้ แต่เวอร์ชันแรกไม่เก็บความจำบทสนทนาระยะยาวนอกเหนือจากข้อมูลที่จด
- ใช้ได้เฉพาะเจ้าของ (ต้องมีการล็อกขั้นต่ำ เช่นอนุญาตเฉพาะตัวตนของเจ้าของ) วิธีทำให้ขั้น design
- สกุลเงินบาท เขตเวลา Asia/Bangkok รับปี พ.ศ. ที่ผู้ใช้พิมพ์ได้
